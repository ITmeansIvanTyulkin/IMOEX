# Кости vs ядро (ось IP)

Три оси нельзя смешивать в один флаг:

| Ось | Что | Статус |
|---|---|---|
| **A. Delivery** | Instance (лёгкий браузер) vs Core (локальный архив / replay) | отложено, осень–зима 2026 |
| **B. Тариф** | 5 000 / 7 500 / 15 000, `imoex.upsell.*` | черновик, биллинга нет |
| **C. IP** | публичные Кости vs закрытое торговое ядро | **сейчас** |

## Что где

- **IMOEX** (этот git, публичный) — Кости: `trinity-shell`, `trinity-app` (оболочка UI), `trinity-shared`, `trinity-marketdata`, LICENSE, README.
- **IMOEX-core** (соседняя папка, не этот remote) — ядро целиком: `trinity-trend`, `trinity-pairs`, `trinity-calendar-arb`. Чек-листы #1/#2 не режутся.

Unlock оператора = ядро на classpath (профиль Maven `operator`, файл `../IMOEX-core/pom.xml`).  
`imoex.run.unlock` / `IMOEX_UNLOCK` — локальный секрет запуска app, не DRM.

Честный предел: если ядро у клиента на JVM, его можно декомпилировать. Защита = не отдавать алгоритмы в публичный клон. Старые коммиты этого GitHub ещё могут содержать монолит; rewrite/force-push не делаем.

Публичный клон:

```bash
mvn -pl trinity-shell -am spring-boot:run
```

GitHub IMOEX остаётся **публичным** (оценка продукта). Ядро — отдельный **private** репозиторий `IMOEX-core`. Форк публичной оболочки не даёт лицензии и не содержит плейбуков в HEAD.

Честный предел: старые коммиты публичного git, сделанные до разреза, могут ещё содержать монолит. Новые клоны HEAD — только Кости. Полная очистка истории потребовала бы delete+recreate репозитория или rewrite (force-push) — этого по правилам оператора не делаем, пока не будет отдельной команды.
